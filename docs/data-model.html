What the phone keeps

An IndexedDB database named taskly, version 1, with two stores:

snapshot
One entry, under the key "current": { data, syncedAt }, where data is the last /api/sync answer.
queue
Task changes not sent yet, keyed by seq (auto-increment, so they go out in the order they were made): { seq, method, path, body, queuedAt }.
  • POST /api/tasks with { id, list_id, title, due_date?, due_time?, due_zone? }
  • PATCH /api/tasks/{id} with { title?, status?, due_date?, due_time?, due_zone? }, where due_date replaces the due date with its time and due_date: null removes it (pages from before statuses sent { title?, done? }, still accepted)
  • DELETE /api/tasks/{id}

A task with a change still waiting is marked pending; that flag exists only on the phone. localStorage holds taskly.list (the open list) and taskly-theme (light or dark, once chosen).

Logging out clears all of it. Logging in as someone else clears both stores first.

Kept by the code, not by SQLite

The schema can't express these. The queries and routes keep them, and the tests check them.

  • The owner is a member tooCreating a list also adds the owner's list_members row, so "which lists can I see" is one lookup. lists.role() relies on it.
  • Accounts are disabled, never deletedNames stay on the tasks people added and finished. A disabled account can't log in, can't be added to a list, and is left out of members.
  • Lists change hands on disabledisable-user gives each list the account owns to the active member who joined earliest (joined_at). With nobody else, the list keeps its disabled owner.
  • An unowned list gets claimedOnly the old "Taskly" list can be unowned, if it was migrated before any account existed. The next add-user takes it (lists.claim_unowned).
  • Who makes the idsThe server makes list ids; the phone makes task ids, so a task can be created offline. The same task sent again to the same list is a retry: 200 and the stored task, unchanged.
  • Finishing records whoMoving a task to done sets done_by to whoever did it; any other status clears it. done: false from an older page reopens only a done task, so it can't undo "in progress". Every task change bumps the task's updated_at.
  • A due date is a dayThe API takes only 2026-10-17 for due_date (422 otherwise), and null in a PATCH removes it. The server never asks what day it is: today, tomorrow and overdue are the phone's call, by its own clock.
  • A time is a momentA time is a 24-hour 15:00 in the IANA zone of whoever set it, checked with Python's zoneinfo: one moment, shown by each phone in its own time, with the time where it was set when that reads differently ("That's 3:00 PM New York time"). Time and zone come together, only with their date, and a new due_date without a time drops the old one; SQLite checks the pairing too.
  • LengthsUsernames are 2–32 letters, digits, ., _ or -. List names are 1–100 characters and titles 1–500, trimmed. Passwords need at least 6.
  • Sessions expire90 days after last_used_at, which is written at most once an hour. Expired rows are deleted at the next login, or when their cookie comes back.
  • Agents connect as a personAn AI agent (Claude, Gemini) signs in through /oauth/authorize and gets a grant: a code is swapped once for an access token (1 hour) and a refresh token (90 days, replaced on every use). Codes and tokens are stored as SHA-256, like sessions. A password change, reset-password, disable-user and revoke-sessions delete the person's grants.
  • Foreign keys are on per connectiondb.connect() runs PRAGMA foreign_keys = ON. SQLite leaves them off otherwise, and the cascades depend on them.

Changing the schema

  1. Append an SQL string to MIGRATIONS in taskly/db.py. Never edit or reorder one that has been deployed: the VM's database already ran it and won't run it again.
  2. Add the change to MODEL in this page (docs/data-model.html): a table, or a column with its since, and any reference.
  3. Open this page in a browser, press Copy the diagram as SVG with the newest version selected, and save it over docs/data-model.svg, the picture in the README.
